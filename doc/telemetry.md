# 本機遊玩紀錄與統計

遊玩紀錄以 Run 為單位，保存玩家已提交的選擇、完整配置與戰鬥結果，供分析平衡、獎勵供給、資源使用及遊玩節奏。資料透過 Dexie.js 存於本機 IndexedDB，以隨機 Run ID 串接，附帶遊戲、平衡與資料格式版本。國家欄位保留空值。

## 保存與管理

本機保留最近 20 局，包含進行中與未完成紀錄。建立新局時依開始時間清理超額舊局，刪除與容量清理均以整局為單位。關鍵操作、回合結果與定時檢查點會保存資料，失焦及頁面隱藏時補存計時。重新整理或關閉後，已保存的進行中紀錄呈現為未完成；遊戲續玩由存檔功能管理。儲存失敗時，panel 顯示原因，遊戲繼續運作。

列表支援多選、全選、刪除及匯出選取紀錄，亦可匯出單局。每次匯出產生一份 JSON，包含選取的所有局及其引用資料。主選單「重置紀錄」負責劇情及偏好設定；遊玩統計由統計 panel 管理。

## 紀錄內容

每局保存開始與最後紀錄時間、平台、內容範圍、難度、抵達節點、行經路線及結果。結果區分通關、死亡、回合上限失敗、重新開始與未完成。區域、篇章及目前發行內容各自建立完成紀錄，保存累計時間與配置。目前鱷魚人篇末戰先記錄戰鬥勝利，最終獎勵處理完畢後記錄本篇及整局通關。

### 候選、選擇與結果

商店進場與刷新、戰利品生成與刷新、寶箱開啟、營火進場與刷新、骰子獎勵生成時，各保存一批玩家可見選項。每項包含穩定 ID、當時名稱、已公開物品、價格及隱藏張數。戰利品的一明一蓋只在候選中記錄明牌；選定後的結果才保存該組全部貼紙。主題包同樣以包名與張數作為候選，開包結果記錄抽到的每張貼紙及取得身分。

成功購買、補血、刷新、領取／替換裝備、營火選擇、選擇／放棄獎勵及選路，各建立決策事件，附節點與累計前景時間。有對應候選時，以 `offerId` 連回原批次，以 `choiceId` 指向選項。滿格替換的購買事件在確認替換並付款時成立。購買包與開包結果分別記錄付款及揭曉，兩者引用同一商品選項。額外戰利品、公主保底及 Boss 新骰也保存實際取得結果。

### 背包與構築

配置快照包含每顆骰子的固定 ID、骰型、順序與每面的 ID、索引、固定點數、永久角色、材質、臨時覆蓋及當場有效角色／基礎攻擊力，同時保存裝備、永久背包、臨時背包、戰前臨時配置、HP／上限、護盾、金幣、Control、朝上骰面與完整土人戰鬥狀態。背包單獨變更也建立配置快照。

貼紙事件保存實例 ID、名稱、取得資料及前後位置，涵蓋收進背包、貼附、移動／交換、取下、放棄與開戰消耗。位置包含待處理獎勵、永久背包、臨時背包、永久骰面與臨時覆蓋；骰面位置附骰子 ID、名稱、面索引及方向。交換事件同時保存雙方移動。臨時貼紙在戰前保留其預配置，確認開戰時記錄消耗，戰鬥快照保留實際覆蓋。

開局、構築變更、戰前準備、首次擲骰、戰鬥結束與完成里程碑建立快照。戰鬥進場配置使用首次擲骰時已套用臨時貼紙的版本；結束配置使用清除臨時貼紙與祝福之前的狀態。角色組成以永久角色面數除以全部骰子的實際總面數，附名稱、面數與分母。裝備持有歷程保存取得／替換節點、來源、替換對象、前景持有時間與參戰次數。

### 資源與耗時

決策事件以明確操作原因保存金幣、HP 與 Control 的前後值，差額即為實付費用或有效收益。來源涵蓋購買、補血、刷新、營火、重骰／裝備操作、放棄補償、回合土人與裝備收益及勝利／鍍金收益。有效治療以上限套用後的 HP 差額計算。戰鬥承傷另由逐回合與逐敵人明細保存。

總經過時間包含背景停留，前景時間只累計視窗聚焦且頁面可見的區間。每局及每個節點另將前景時間分為商店、獎勵選擇、骰面配置、戰鬥操作、戰鬥演出、營火、選路與其他，各分類總和等於前景時間。開啟骰面檢視或貼紙編輯器時歸入配置，重骰動畫歸入演出；計時反映當時遊戲狀態，包含該狀態下的閱讀與停留。

### 戰鬥、重骰與反制

每場戰鬥保存節點／路線、敵人實例、進出場配置、耗時、回合與結果。回合保留初擲、提交結算前及回合結束狀態，並保存輸出、實際造成的 HP／盾損失、承受 HP 傷害、吸收、有效治療、技能／材質觸發、追加及再攻擊數。死亡另保存致死階段、招式、傷害來源與受擊前後狀態。

每顆骰子每次實際套用重骰結果記一次，包含手動、老師與連鎖。明細保存原因、老師來源、骰子身分、重骰前後面索引／角色／基礎值及方向導引前的原始落點；費用由該事件的資源差額取得。連鎖逐步完成時逐步記錄，初擲與翻面使用各自狀態或操作紀錄。平均每場重骰次數以已結束戰鬥的總次數除以場數，包含勝利與失敗。

每回合依敵人實例與來源彙總招式明細：實際出手次數、原始傷害、HP 損失、護盾吸收、反制是否觸發及行動是否取消。鉤索與本回合招式分列，遭取消的行動保留零傷害及反制結果。原始傷害保留溢傷，HP 損失以上限扣血計算；已提交的攻擊事件形成累計明細，動畫中斷時保留完成部分。

## 隱藏入口與 panel

主選單右下角有約 20 × 20 CSS px 的透明入口，第一次點擊啟用、第二次開啟 panel；離開主選單或關閉 panel 後回復雙擊流程。主選單亦支援 Shift + S，Esc 或關閉按鈕關閉 panel。輸入欄位、輸入法組字及長按重複事件沿用原本輸入行為。

panel 保留構築、本局表現及歷程三頁。構築顯示角色比例、裝備、骰池、兩類背包及臨時預配置；表現顯示總覽、分階段耗時、逐場／逐回合資料及可展開的敵人招式明細；歷程以節點分組顯示候選批次與操作，展開可看取得結果、收支、重骰前後及貼紙位置變化，下方保留配置與裝備持有歷程。

## 單檔引用格式

格式版本 3 採 `references-v1`：頂層 `runs` 保存局資料，`records` 保存共用內容，`{"$ref":"face:0"}` 等物件引用同一檔案內的資料。骰面、骰子、裝備、敵人、招式、土人狀態、貼紙及配置定義依完整內容去重；同一遊戲 ID 的內容若曾變動，會保留各自版本。每局包含當時角色、裝備、材質及敵人的設定目錄，相同目錄可跨局共用。引用資料可包含其他引用，遞迴還原即可得到完整原始結構。

此格式保留重複快照的所有時點與欄位，只集中保存相同內容。每份匯出自足，還原依據來自該檔案。`schemaVersion` 表示匯出結構，每局另保留原本版本；`units` 與 `definitions` 提供單位及口徑。時間使用毫秒，時間戳使用 Unix epoch 毫秒，百分比使用 0 至 100。

IndexedDB 使用相同編解碼方式保存每局，讀取時還原成 panel 使用的完整模型。既有完整格式紀錄可直接讀取及重新匯出，原始版本與內容持續保留；舊紀錄省略的新欄位代表「未記錄」，新紀錄的零或空清單表示當時確實為零或尚無事件。

## 實作與驗證

紀錄、引用編碼與分析集中於 `src/service/telemetry/`，介面集中於 `src/components/telemetry/`。`src/configs/telemetryConfig.ts` 統一管理容量、版本、分類名稱與入口設定，目前平衡版本為 `2026-10-08-sisters-share-x3`。商店、獎勵、背包與戰鬥操作在成功提交後送出決策資料，recorder 維護隔離的分析模型。

核心測試涵蓋去重還原、版本區分、舊資料讀取、候選與揭曉、交易費用、有效治療、背包移動／消耗、前景分類計時、逐步重骰及逐敵人承傷／反制，並保留既有組成、裝備、勝敗、完成與容量測試。UI 以型別、建置及程式審查驗證。
