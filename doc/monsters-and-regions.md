# 怪物與關卡設計

> 版本：2026-09-05
>
> 規格入口：[spec.md](spec.md)

本文件管理六區關卡、怪物、Intent、骰子里程碑與戰鬥成長目標。正式版完成六區，Demo 完成前三區。怪物設定採固定 HP、起始護盾與結構化招式序列，數值依代表性輸出情境校準。各區節點數、精確里程碑位置與骰面內容在對應進度設定階段確定。

## 1. 體驗與節奏

玩家先看懂敵人的威脅，再根據骰況決定是否投入 Control、保留組合或承受攻擊。普通怪各有一個核心特色，Boss 透過熟悉招式的順序形成壓力。每回合的主要 Intent 以一行完整交代時機、效果與應對條件。

普通戰提供快速勝利與小幅成長，菁英檢查資源分配，Boss 驗證該區的構築成果。新骰子與高品質貼紙帶來下一段可立即嘗試的組合。失敗資訊呈現致命 Intent、剩餘敵人 HP 與未使用資源，讓玩家能指出下一輪想改變的選擇。

## 2. 六區進度與骰子里程碑

玩家以三顆骰子開局，沿固定里程碑擴大至十顆。新增骰子、永久貼紙與裝備共同構成成長；新骰的取得時間須留下足夠戰鬥，讓玩家貼面、調整組合並使用成果。

| 區域 | 骰池變化 | 新骰取得階段 | 區域任務 |
| --- | --- | --- | --- |
| 第一區・苔石林徑 | 3 → 4 | 中段取得一顆 | 學會 Intent、打斷與破盾，形成第一個構築方向 |
| 第二區・熔雷斷崖 | 4 → 6 | 中段一顆，Boss 勝利後一顆 | 擴展協同，掌握爆發與休整時機 |
| 第三區・命運神殿 | 6 → 8 | 前段與中段各一顆 | 讓核心組合穩定運作，完成 Demo |
| 第四區・逆鐘工坊 | 8 → 9 | 中段取得一顆 | 面對緊湊攻勢，補足構築弱點 |
| 第五區・碎星王庭 | 9 → 10 | 前段取得一顆 | 整合最後一顆骰子，完成整池分工 |
| 第六區・終局之座 | 維持 10 | 使用完整骰池 | 最後整備與終局考驗 |

第一至第五區以一般戰鬥、寶箱、商店、菁英與區域 Boss 組成路線。一般戰鬥從該區怪物池配置，菁英與 Boss 承接該區教過的 Intent。實際節點數與里程碑索引依獎勵頻率、戰鬥時間與新骰使用機會確定，怪物池數量代表可配置內容。

第六區採五節點終章：`一般戰鬥 → 貼紙包獎勵 → 菁英 → 最後商店 → 最終 Boss`。貼紙包沿用即時開包流程，商店提供回血、一次性貼紙與裝備整備。玩家以十顆骰子完成三場終章戰鬥。

Demo 在擊敗第三區的命運守門人摩洛斯後結束。正式版在區域 Boss 勝利後進入下一區，擊敗第六區的骰之支配者後完成 Run。菁英從獨立高價值獎勵池提供永久貼紙、裝備與構築資源，區域 Boss 提供階段獎勵與通往下一區的進度。普通戰鬥的貼紙包 Jackpot 維持一般怪物專用。

## 3. 骰池與獎勵成長

新骰的初始基礎輸出以略低於同階段典型已培養骰子的平均為校準起點，並保留可透過貼紙改善的骰面。取得新骰時，增加的攻擊次數與協同位置共同提供戰力提升。各里程碑使用固定設定內容，設定值依代表性構築驗證。

同等平均輸出的骰子從三顆增加至四顆時，基礎總輸出增加約 33%；九顆增加至十顆時約增加 11%。此比例只描述基礎加總，實際增幅還包含角色支援、搶奪、追加攻擊、再攻擊與裝備效果，須以完整結算檢查。

區域進度提高新取得貼紙的數值品質，永久貼紙負責持續培養，單場一次性貼紙提供較高的短期效果。每張貼紙取得時的內容固定，後續保留原有內容。戰鬥、寶箱、貼紙包與商店的品質曲線一起校準，菁英獎勵集中於該區的高價值內容。

第五區保留永久貼紙與貼紙包的成長機會，第六區延續終盤品質供最後調整。構築完成度依骰子用途、組合穩定度與應對能力評估；低數值功能面與早期 Pattern 零件可持續擔任核心。

## 4. Intent 共通規則

### 4.1 文案與參數

Intent 採「招式：效果；條件」的句型，每行至多一個判定條件。下表與怪物表使用設計參數，玩家介面顯示實際數字。普通怪各自設定數值；同一隻怪的個別招式也可使用各自的攻擊值。

| 參數 | 意義 |
| --- | --- |
| A | 普通攻擊傷害 |
| B | 強攻傷害 |
| S | 取得的護盾量 |
| T | 本回合累計受傷門檻 |

| 行為 | 一行 Intent 範本 |
| --- | --- |
| 攻擊 | 重拳：造成 A 傷害。 |
| 防禦 | 石甲：獲得 S 護盾。 |
| 打斷攻擊 | 巨石投擲：造成 B 傷害；本回合受傷達 T 則取消。 |
| 削弱攻擊 | 雷息：造成 B 傷害；本回合受傷達 T 則減半。 |
| 破盾削弱 | 甲殼衝撞：造成 B 傷害；護盾耗盡則減半。 |
| 阻止防禦 | 映照：獲得 S 護盾；本回合受傷達 T 則取消。 |
| 蓄力預告 | 蓄力：本次蓄力，下回合造成 B 傷害。 |
| 休整 | 喘息：本次休息。 |

### 4.2 時機與結算

當前 Intent 在本次玩家攻擊結算後執行，標示「下回合」的效果則由下一個 Intent 執行。蓄力回合專注預告下一招，下一回合顯示該招的完整傷害與應對條件。喘息、整羽、校準與收勢都是休整行動。

本回合受傷量累計敵人護盾吸收與 HP 實際扣除的傷害，各段傷害計入一次。骰子攻擊、特殊效果與裝備追加傷害均參與累計，回合開始時歸零。玩家整池攻擊結束後，系統先確認敵人存活，再判定 Intent 條件與執行結果。

破盾條件在該招執行時檢查敵人護盾是否為零，提前耗盡護盾同樣有效。護盾消耗沿用戰鬥規則，剩餘量跨回合保留。減半傷害向上取整，介面顯示取整後的實際結果。

一般招式序列從第一招開始，執行或取消後前進一格，最後一招結束後回到循環起點。標示「起手護盾」的怪物在戰前準備時顯示初始護盾，後續執行表列循環；初始護盾只提供一次。其餘取得護盾的招式依序列執行。

### 4.3 讀取與應對

玩家在戰前準備查看敵人與起手 Intent，選擇一次性貼紙；配置在開戰後持續整場。Control 階段根據目前骰況預覽敵人行動結果，顯示「可打斷」或「尚差 3」等簡短提示，重骰後同步更新。

必要條件採累計傷害或護盾耗盡，所有攻擊類型均可參與。玩家能選擇追求門檻、用護盾或 HP 承受後果、保留 Control，或在敵人行動前擊殺。敵人的特色由攻勢密度、準備時間、可削弱幅度與休整位置構成。

## 5. 第一區・苔石林徑

本區教玩家辨識攻擊、預告、打斷與破盾。鼓泡史萊姆建立閱讀習慣，喀啦展示補足少量傷害的作用，荊背岩豬提供破盾後的直接回饋。苔冠巨像與穆爾以熟悉招式檢查資源分配。

| 怪物 | 定位 | 招式序列 | 代表 Intent |
| --- | --- | --- | --- |
| 鼓泡史萊姆 | 普通 | 輕擊 → 膨脹 → 重擊 | 膨脹：本次蓄力，下回合造成 B 傷害。 |
| 投石哥布林・喀啦 | 普通 | 巨石投擲 → 普攻 | 巨石投擲：造成 B 傷害；本回合受傷達 T 則取消。 |
| 荊背岩豬 | 普通 | 起手石甲；衝撞 → 喘息 → 普攻 | 甲殼衝撞：造成 B 傷害；護盾耗盡則減半。 |

## 11. 數值校準與驗證

### 11.1 戰鬥目標

以下回合數是同區典型構築的初始測試目標。構築依該進度可取得的骰子、貼紙、裝備與資源建立，另以偏弱與偏強狀態檢查敏感度。回合數由第一次擲骰開始計算，包含擊殺回合；首版偏弱情境的中位回合數可比目標上限增加兩回合。

| 戰鬥類型 | 目標回合數 | 體驗 |
| --- | --- | --- |
| 一般戰鬥 | 2～3 | 快速處理威脅並取得成長；強構築可一回合擊殺 |
| 菁英 | 3～4 | 為明確威脅投入有限資源 |
| 區域 Boss | 4～5 | 驗證區域內建立的構築與決策 |
| 最終 Boss | 5～6 | 使用完整骰池與最後整備成果 |

敵人 HP 與護盾依完整結算後的輸出分布校準，攻擊依玩家生命、護盾、補給與預期承受行動數校準。一般怪條件失敗的代價以可承受傷害或有限護盾為主。護盾循環須讓偏弱但合理的構築持續削減敵人 HP。

傷害門檻同時涵蓋已達標、接近達標與明顯不足的骰況，讓玩家能分別選擇收手、重骰或保留資源。新骰、永久貼紙與裝備的增益須一起計算，並檢查高骰數時的 Pattern 發動率、連鎖放大與每次貼面的相對收益。

### 11.2 代表情境與通過條件

驗證涵蓋各區入口、新骰取得前後、區域 Boss 與最終 Boss；構築包含高數字、土人群體、搶奪連鎖、生存，以及保留早期功能面的混合構築。每種構築檢查低、中、高擲骰結果，並比較零 Control 與有剩餘 Control 的決策。

先以喀啦、荊背岩豬、鏡骰裁決官與穆爾驗證取消攻擊、削弱攻擊、阻止護盾及招式組合。遊玩測試觀察玩家能否約三秒內說出 Intent 後果，並指出本回合保留或使用 Control 的理由。若決策始終只追最高傷害，調整門檻、代價與休整位置後重新測試。

確定性測試涵蓋傷害門檻前一點、恰好達標、超過門檻、護盾提前耗盡、減半取整、取消後序列前進，以及敵人死亡後直接進入勝利。固定種子的批次模擬記錄戰鬥回合、玩家失血、Control 消耗、打斷率與獎勵成長，判斷代表構築是否符合目標。

### 11.3 首版 config 校準

首版先用整池每回合輸出作為校準輸入，第一至第六區的參考值依序為 12、26、50、75、105、125。這些值包含預期組合增益，是等待各區實際構築驗證的假設；實戰讀取每隻怪物的固定數值。開局骰池的全部擲骰結果由[核心計算驗證](../src/service/battle/enemies/monsterBalance.test.ts) 讀取目前的土人骰面與裝備設定，列舉零 Control、空儲糧的平均傷害與範圍。第一區參考值涵蓋少量培養與結果修正，後續區域依實際取得內容重新校準。

固定種子為 20260905，每隻怪物各跑 512 次偏弱、典型與偏強輸出情境，共 39,936 場。三種情境分別採參考輸出的 70%、100% 與 140%，每回合在該值的 70%～130% 間均勻取樣並四捨五入。模擬沿用正式傷害與 Intent 結算，玩家使用無限 HP 以量測擊殺前的傷害暴露量。Control 決策、玩家護盾、具體裝備觸發與路線補給留待完整 Run 驗證。

| 戰鬥類型 | 典型輸出中位回合 | 偏弱輸出中位回合 |
| --- | --- | --- |
| 一般戰鬥 | 2～3 | 3～4 |
| 菁英 | 4 | 5～6 |
| 區域 Boss | 4～5 | 6～7 |
| 最終 Boss | 6 | 8 |

本次所有情境都在 40 回合上限內完成擊殺，最低輸出下每輪傷害也高於護盾循環的補充量。典型輸出面對最終 Boss 的平均傷害暴露量約 45.5，後續須連同玩家 60 點初始生命、護盾與補給一起檢查存活率。上述結果支持首版耐久與招式門檻，完整路線的難度仍由實際構築與遊玩測試確認。

執行 `npm run test:monsters` 可重跑怪物結構、Intent 邊界、實際戰鬥結算、文字渲染與輸出情境測試。模擬程式位於 [monsterBalanceSimulation.ts](../src/service/battle/enemies/monsterBalanceSimulation.ts)，參數與通過範圍集中於下列數值驗證基準。

### 土人版初版驗證紀錄

[土人組合矩陣](../src/service/battle/creatures/tribalMatrix.test.ts) 直接讀取目前角色、貼紙與裝備設定，每種骰池以固定種子抽樣 500 次，驗證重骰終止、預覽穩定、各事件數值連續及逐筆傷害無條件進位後的攻擊清單總和一致。中後期案例使用五件完整裝備，是構築壓力案例。

| 案例 | 平均傷害 | P10／P50／P90 | 最大追加骰數 |
| --- | --- | --- | --- |
| 初始 3 骰、空裝備 | 10.86 | 9／10／13 | 0 |
| 6 骰、中期貼紙、五件裝備 | 74.86 | 56／75／93 | 3 |
| 10 骰、後期貼紙、五件裝備 | 174.13 | 140／174／212 | 4 |

初始三骰另外列舉全部 216 種擲出結果，平均傷害 10.81、範圍 8～18，符合第一區 12 傷害參考值的 ±20% 驗證範圍。完整裝備組合已有較高輸出，後續實玩以取得速度、Control 支出與各區實際勝率校準。六區怪物的既有輸出預算測試驗證回合目標；土人抽樣矩陣驗證實際計算與代表組合，兩者各自保留驗證用途。

## 12. 設定檔與修改入口

怪物設定集中於 `src/configs/monsters`，共用既有戰鬥流程。招式以名稱、類型、數值與至多一個條件描述，文案從設定產生。現行九節點原型透過怪物 ID 配置第一區敵人，並沿用既有骰子里程碑與獎勵內容，供招式接入驗證。六區路線與骰子獎勵接續在各自的設定階段完成，完整 Run 的存活率在路線與補給確定後驗證。

| 修改項目 | 目前設定入口 | 對應內容 |
| --- | --- | --- |
| 怪物與招式數值 | [monsterConfig.ts](../src/configs/monsters/monsterConfig.ts) | `MONSTER_CONFIG`：26 隻怪物、區域、定位、HP、起始護盾與 Intent 序列 |
| 數值驗證基準 | [monsterBalanceConfig.ts](../src/configs/monsters/monsterBalanceConfig.ts) | 各區參考輸出、戰鬥回合目標與固定種子模擬參數 |
| 地圖節點 | [gameConfig.ts](../src/configs/gameConfig.ts) | `INITIAL_MAP_NODES`：節點類型、順序與名稱 |
| 開局骰池 | [initialDiceConfig.ts](../src/configs/creatures/initialDiceConfig.ts) | `INITIAL_DICE_POOL`：角色、基礎值與骰面配置 |
| 角色能力與數值 | [土人骰面與結算規則](tribelings.md) | 角色標籤、能力參數與核心結算入口 |
| 土人貼紙 | [creatureStickerConfig.ts](../src/configs/creatures/creatureStickerConfig.ts) | 基礎值、階段成長、價格與永久／一次性貼紙 |
| 裝備資料 | [gameConfig.ts](../src/configs/gameConfig.ts) | `ALL_EQUIPMENT_CATALOG` |
| 新骰里程碑 | [diceProgressionConfig.ts](../src/configs/diceProgressionConfig.ts) | `PROGRESSION_DICE_REWARDS`：取得位置與新骰內容 |
| 獎勵數量與權重 | [rewardConfig.ts](../src/configs/rewardConfig.ts) | `REWARD_CONFIG`：普通戰與寶箱的候選、類型權重 |
| 貼紙包 | [stickerPacksConfig.ts](../src/configs/stickerPacksConfig.ts) | `STICKER_PACKS_CATALOG`：張數與內容池 |
| 商店價格與補給 | [shopConfig.ts](../src/configs/shopConfig.ts) | 商店價格與回血設定 |

怪物資料結構由 [enemy.ts](../src/types/enemy.ts) 定義，節點選怪由 [nodeService.ts](../src/service/battle/nodeService.ts) 處理。[enemyIntent.ts](../src/service/battle/enemies/enemyIntent.ts) 提供共用條件判定，[battleSettlement.ts](../src/service/battle/battleSettlement.ts) 執行結果，[EnemyCard.tsx](../src/components/battle/EnemyCard.tsx) 呈現由 [enemyDescription.ts](../src/service/battle/enemies/enemyDescription.ts) 產生的 Intent。上述入口共同讀取對應 config，保持預告、判定與實際結果一致。
